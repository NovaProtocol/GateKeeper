Gateway

Applies only when no group matches the host. Enforced by shared/gate.py:resolve_rule_action in both gate paths. It cannot override the case where a group matched but its catch-all is missing: that is always refused, whatever this says. In a healthy database the seeded *.*/* group matches every host, so this is a backstop for a missing default group rather than a per-host policy.

Counted in api/app.py:check_rate_limit over the last 60s of audit_logs for that IP, per IP.

Sessions

Sets both the cookie's Max-Age and the JWT's exp, in auth-gateway/app.py:_set_auth_cookie and _set_custom_cookie. They move together on purpose: a cookie that outlives its own token is a cookie that fails on the next request. This does not change the manage_session cookie, which stays at its own 8 hours. An admin session and a visitor session are different trust levels and do not share one dial.

Maintenance

serve 503 to every gated host

Checked in auth-gateway/app.py:_maintenance_response before rule dispatch, so it means the same thing on every host. /manage and /manage/login are exempt, which is why this page stays reachable to switch it back off. The API is unaffected, so X-Internal-Api-Key callers still work.

Rendered into shared/error_pages.py:render_maintenance_html, escaped. Leave it blank to say nothing extra.

Audit

Used by api/app.py:prune_audit_logs, which runs once at API startup and whenever the button below is pressed. There is no scheduler: nothing ages rows out while the API keeps running. Currently sourced from the {{ environment.log_retention_source }}.
